# Just For You

یک تجربهٔ دیجیتالیِ سینمایی و شخصی — ساختهٔ رهام، برای ستاره.
React + Vite + TypeScript + Framer Motion + Lucide. بدون بک‌اند، بدون آنالیتیکس، بدون ارسال هیچ داده‌ای به بیرون.

> **وضعیت راستی‌آزمایی:** کد این پروژه بدون اجرای `npm install` و `npm run build` نوشته شده (محیطی که پروژه در آن ساخته شد به اینترنت دسترسی نداشت).
> اسکریپت‌های داده (`verify`, `approve`, `check-dist`) و ابزار بازبینی اجرا و تست شده‌اند، ولی **بیلد کامل و تست روی گوشی انجام نشده**.
> قبل از انتشار، مراحل «تست روی اندروید» و «چک‌لیست انتشار» را خودت انجام بده. اگر `npm run build` خطایی داد، متن خطا را بفرست تا درست شود.

## ۱. نصب

نیازمندی: Node.js نسخهٔ ۱۸ یا بالاتر (پیشنهاد: ۲۰).

```bash
npm install
```

## ۲. اجرا و بیلد

```bash
npm run dev        # اجرای محلی، معمولاً http://localhost:5173
npm run build      # بررسی داده‌ها + ساخت پوشهٔ dist + بررسی نهاییِ خروجی
npm run preview    # دیدن نسخهٔ بیلدشده
npm run typecheck  # بررسی نوع‌ها (اختیاری)
```

`npm run build` سه کار می‌کند: (۱) درستیِ داده‌های پیام‌ها را چک می‌کند، (۲) سایت را می‌سازد، (۳) مطمئن می‌شود هیچ پیامِ تأییدنشده‌ای در `dist` نیست. اگر هرکدام خطا بدهد، بیلد متوقف می‌شود.

## ۳. ویرایش متن‌ها

همه‌چیز در پوشهٔ `src/data/` است؛ لازم نیست کدِ React را بفهمی.

| فایل | محتوا |
| --- | --- |
| `src/data/letters.ts` | نامهٔ ورودی، سه نامه، نامهٔ آخر، صفحه‌های دفتر، یادداشت‌های پنهان |
| `src/data/siteConfig.ts` | نام‌ها، **رمز**، پیام‌های خطای رمز، راهنما، عنوان و توضیح فصل‌ها، مسیر موسیقی |
| `src/styles/tokens.css` | همهٔ رنگ‌ها، فونت‌ها و اندازه‌ها (سیستم طراحی) |

نکته‌ها:
- هر پاراگراف نامه یک رشتهٔ جدا داخل آرایه است. کافی است متنِ داخل `' '` را عوض کنی.
- جملهٔ پایانیِ نامهٔ آخر (`تو برام آدم خاصی هستی.`) در `closing` است.
- چهار یادداشت پنهان (ستارهٔ صفحهٔ اصلی، صورت فلکی، هلال، تکهٔ نامه) در `discoveries` هستند. بعضی‌شان به چیزهای واقعیِ گفتگو اشاره دارند (اولین تبریک، اسمِ ذخیره‌شده، قولِ گیتار). مطمئن شو که با همه‌شان راحتی.
- برای عوض‌کردن رنگ‌ها فقط `src/styles/tokens.css` را ویرایش کن.
- اگر `siteConfig.storageKey` را عوض کنی، پیشرفتِ ذخیره‌شدهٔ همه صفر می‌شود.

## ۴. تأیید و افزودنِ پیام‌ها (خاطرات ما)

اصل: **هیچ پیامی بدون تأییدِ صریحِ تو وارد سایت نمی‌شود.** تا وقتی چیزی تأیید نکنی، فصل «خاطرات ما» یک پیام ملایمِ «در حال نوشته‌شدن» نشان می‌دهد و بقیهٔ سایت عادی کار می‌کند.

**چطور استخراج شد:** فایل HTML بکاپ بررسی شد. هر پیام یک بلوک `msg in|out` با ساعت و متن است و تاریخ‌ها از جداکننده‌های `date` می‌آیند.
- `out` = صاحبِ اکانتِ بکاپ‌گیرنده (**رهام**؛ تأیید ساختاری: پیام‌های رباتِ «Self Spider» که با اکانت خودِ رهام ارسال شده‌اند هم `out` هستند و در متن چت هم بارها اشاره شده که نام «غلام رضا» در گوشی رهام برای ستاره ذخیره است).
- `in` = طرف مقابل (**ستاره**).
- تاریخ‌ها میلادی‌اند، همان‌طور که در فایل بودند (`2026/10/22`). ساعت‌ها با ثانیه ذخیره شده‌اند. منطقهٔ زمانی در فایل مشخص نیست.
- متن‌ها عیناً کپی شده‌اند؛ هیچ پیامی ساخته یا ویرایش نشده.

**چه چیزی کنار گذاشته شد:** رسانه‌ها (عکس، ویس، استیکر، گیف، موزیک، ویدیو)، پیام‌ها و خروجی‌های ربات/سلف، لینک‌ها، هر گفتگو دربارهٔ رابطه‌های قبلیِ هر دو طرف، گفتگوهای مربوط به حال بد و مسائل خصوصیِ دو طرف، پیام‌های حاوی فحش، و گفتگوی شب ۲۶ اکتبر (اعتراف و پاسخ‌ها).

**۱۷ قطعه (۹۶ پیام) برای بازبینی پیشنهاد شده**، در سه گروه: شوخی، خاطره‌های مشترک، حرف‌های ماندگار. (در گروه «حرف‌های ماندگار» عمداً فقط دو قطعه هست؛ بقیهٔ گفتگوهای عمیق یا به رابطه‌های قبلی ربط داشتند یا خصوصیِ ستاره بودند.)

**مراحل تأیید:**
1. فایل `review/review.html` را در مرورگر باز کن (روی گوشی هم کار می‌کند).
2. برای هر پیام «تأیید» یا «ردّ» را بزن. دکمهٔ «تأییدِ همهٔ این قطعه» فقط میان‌بُر است و برای همهٔ پیام‌های همان قطعه تأیید ثبت می‌کند. هدف: حدود ۱۰ پیام (یا چند قطعهٔ کوچک).
3. یکی از این دو راه:
   - **راه الف (کامپیوتر):** «دانلود approvals.json» را بزن، فایل را در `review/` بگذار و اجرا کن: `npm run approve`.
   - **راه ب (فقط گوشی/گیت‌هاب):** «کپی approvedMessages.ts» را بزن و کل محتوای فایل `src/data/approvedMessages.ts` را با آن جایگزین کن.
4. `npm run build` را بزن. اگر پیامی دستی تغییر کرده یا اصلاً در فهرست کاندیدها نبوده باشد، بیلد با خطا متوقف می‌شود.

> پیام‌های هر قطعه فقط به‌صورت تأییدشده نمایش داده می‌شوند. اگر وسطِ یک قطعه پیامی را رد کنی، بین پیام‌ها نشانهٔ «···» می‌آید.

## ۵. فرستادن تغییرها به GitHub

```bash
git init
git add .
git commit -m "Just For You"
git branch -M main
git remote add origin https://github.com/USERNAME/just-for-you.git
git push -u origin main
```

**مخزن را حتماً Private بساز.** فایل‌های `src/data/messageCandidates.ts` و `review/review.html` متنِ کاندیدها (از جمله پیام‌های ردشده) را دارند. این فایل‌ها وارد سایت منتشرشده نمی‌شوند، ولی در مخزن هستند. اگر می‌خواهی مخزن کاملاً تمیز باشد، بعد از تأیید نهایی می‌توانی `review/review.html` را حذف کنی و در `messageCandidates.ts` فقط قطعه‌های تأییدشده را نگه داری (یا آرایه را خالی کنی؛ سپس `npm run verify` اجازهٔ هیچ پیام تأییدشده‌ای را نمی‌دهد، پس این کار را فقط وقتی انجام بده که `approvedMessages.ts` را دیگر تغییر نمی‌دهی و `verify` را از `build` برداشته‌ای).

## ۶. اتصال GitHub به Netlify

1. در Netlify: **Add new site → Import an existing project → GitHub** و مخزن را انتخاب کن (برای مخزن Private باید دسترسی Netlify به گیت‌هاب را بدهی).
2. تنظیمات از `netlify.toml` خوانده می‌شود، ولی بررسی کن:
   - Build command: `npm run build`
   - Publish directory: `dist`
   - متغیر محیطی `NODE_VERSION = 20` (در `netlify.toml` هست).
3. **Deploy** را بزن. از این به بعد هر `git push` به شاخهٔ `main`، سایت را خودکار به‌روز می‌کند.

## ۷. تنظیمات بیلد Netlify (خلاصه)

| مورد | مقدار |
| --- | --- |
| Build command | `npm run build` |
| Publish directory | `dist` |
| Node | 20 |
| Redirect / fallback | لازم نیست؛ مسیریابی با `#/c/...` (hash) است |
| هدرها | `noindex`، `no-referrer`، کش طولانی برای `/assets` (در `netlify.toml`) |

هیچ کلید یا secret ای در پروژه نیست و هیچ‌چیز به ماشین محلی وابسته نیست.

## ۸. محدودیت‌های رمزِ سمتِ کاربر ⚠

رمز (`ستاره`) در مرورگر چک می‌شود و در کدِ جاوااسکریپتِ سایت (و در متن نامه‌ها و پیام‌ها) هست. هر کسی که آدرس سایت را داشته باشد و کمی فنی باشد می‌تواند از رمز عبور کند یا مستقیم محتوا را از فایل‌های جاوااسکریپت بخواند. پس:

- این رمز یک **«در بازِ تشریفاتی»** است، نه قفل امنیتی. سایت را «خصوصی» یا «امن» حساب نکن.
- فقط چیزهایی را منتشر کن که اگر کسی غیر از ستاره هم دید، مشکلی نیست.
- آدرس Netlify را فقط برای ستاره بفرست و جایی منتشر نکن (سایت `noindex` است، ولی این هم حفاظت نیست).

اگر حریم خصوصیِ واقعی لازم است، یکی از این‌ها:
1. **Netlify Password Protection / Site-wide protection** (طرح‌های پولی Netlify): رمز در سرور چک می‌شود و فایل‌ها بدون رمز تحویل داده نمی‌شوند.
2. **Cloudflare Access** یا هر پراکسیِ احراز هویت جلوی سایت (ورود با ایمیلِ ستاره).
3. **Netlify Edge Function / Function** که رمز را سمت سرور چک کند و فقط بعد از آن محتوا را بدهد (محتوا نباید داخل باندل استاتیک باشد).
4. آدرسِ غیرقابل‌حدس + حذف سایت بعد از دیده‌شدن (محافظت ضعیف، ولی عملی).

## ۹. تست روی اندروید

1. `npm run dev -- --host` را اجرا کن؛ گوشی و کامپیوتر باید روی یک وای‌فای باشند. آدرسِ `Network` را در Chrome گوشی باز کن (یا آدرس Netlify را).
2. مواردی که تست کن: ورود و باز شدن نامه، رمز غلط (پیام‌های خطا و لرزش) و رمز درست، تایپ فارسی در کادر رمز، منو و رفتن بین همهٔ ۷ فصل، دکمهٔ بازگشت اندروید (باید یک فصل برگردد)، جستجو و فیلتر در «خاطرات ما» (اگر پیامی تأیید کرده‌ای)، صفحه‌های دفتر، سه کشف در «چیزهای کوچیک»، چرخش صفحه، متن بلند روی صفحهٔ باریک، اسکرولِ روان.
3. ازحالت خودکار «Reduce motion» (تنظیمات دسترسی‌پذیری اندروید → Remove animations) هم یک بار تست کن؛ همه‌چیز باید بدون انیمیشن هم خوانا و قابل‌استفاده باشد.
4. بعد از بستن و باز کردنِ دوبارهٔ سایت، باید دو دکمهٔ «ادامه بدیم» و «از اول شروع کنیم» ببینی.
5. از منو → «پاک کردن حافظهٔ این مرورگر» را تست کن؛ همه‌چیز باید از اول شروع شود.

## ۱۰. چک‌لیست حریم خصوصی قبل از انتشار

- [ ] مخزن GitHub **Private** است.
- [ ] هر پیامِ تأییدشده را یک بار دیگر خواندی و با انتشارش راحتی (خصوصاً پیام‌های ستاره).
- [ ] `npm run build` پیام «خروجی (dist) تمیز است» را نشان می‌دهد.
- [ ] در `dist/` دنبال اسم‌هایی بگرد که نباید باشند (`grep -r "نام" dist`).
- [ ] نامه‌ها و یادداشت‌های پنهان (`letters.ts`) را برای آخرین بار خواندی؛ مخصوصاً بخش‌هایی که به خاطره‌های واقعی اشاره دارند.
- [ ] می‌دانی رمز امنیتِ واقعی نیست (بخش ۸).
- [ ] آدرس سایت فقط برای ستاره فرستاده می‌شود.
- [ ] فایل‌های بکاپِ اصلیِ چت (HTML) داخل پروژه یا مخزن **نیستند**.

```
src/
  components/   Sky (ماه و ستاره‌ها)، Reveal، NoteCard، ChapterShell، SettingsSheet
  pages/        Intro، Resume، Gate، Home، Memories، Diary، LetterPage، Small
  data/         siteConfig، letters، messageCandidates، approvedMessages، types

  lib/          persian (نرمال‌سازی و تاریخ)، storage
  styles/       tokens.css (سیستم طراحی)، base، sky، screens، chapters
scripts/        verify-data، apply-approvals، check-dist
review/         review.html (ابزار تأیید پیام‌ها)
```

## ذخیرهٔ پیشرفت

فقط در `localStorage` همین مرورگر: فصل‌های دیده‌شده، یادداشت‌های پیداشده، میزان خواندن، موقعیت اسکرول، صفحهٔ دفتر، و اینکه رمز را زده یا نه. داده‌ی خراب یا ناموجود نادیده گرفته می‌شود. «از اول شروع کنیم» مقدمه و رمز را دوباره نشان می‌دهد ولی یادداشت‌های پیداشده می‌مانند؛ «پاک کردن حافظه» (در منو) همه‌چیز را صفر می‌کند. هیچ آنالیتیکسی وجود ندارد و هیچ‌چیز به بیرون فرستاده نمی‌شود.

## موسیقی (اختیاری، در آینده)
